Feature 000: Domain Policy（MVPの共通仕様）を spec 化して。
出力先は specs/000-domain-policy/spec.md。

前提：
- モジュール：web-api / ios-patient / ios-family
- 技術：Next.js, SwiftUI, Supabase(Auth+DB), Prisma, PostgreSQL, Vercel(無料範囲)
- 認証：
  - 家族：メール＋パスワード（Supabase Auth）
  - 患者：連携コードのみで利用（患者単独ログインID/パスワードは持たない）
- 連携：
  - 家族は複数患者を管理
  - 連携コードはワンタイム（患者が登録したら無効化）
  - 連携解除はUIから可能。解除後、家族は過去も含め患者データ閲覧不可（患者データ自体は保持）
- 服用記録：
  - 患者は「飲んだ」を記録できる
  - 家族も代理で「飲んだ」を記録できる
  - 服用記録の修正/取り消しは不可
  - 服用記録には recordedBy（patient/family）と recordedByUserId を必ず保存
- 未服用（MISSED）：
  - 予定時刻から60分超でサーバーが未服用レコードを作る（ジョブ）
  - 60分超の後に「飲んだ」が入った場合、未服用は残しつつ resolvedAt を付けて解消（RESOLVED）扱いにする
- 予定の時刻：
  - 朝/昼/夜/眠前の具体時刻は「患者ごとに家族が設定」できる（時間帯→時刻に変換）
- 在庫：
  - 在庫減算は TAKEN（飲んだ）のときのみ。MISSEDでは減算しない
  - 家族は在庫を手動で補充（在庫数を増やす）できる
  - 在庫が少ない薬は警告を出し、一覧上部に表示（しきい値はMVPとしてデフォルト値を定義。設定可能は将来拡張でもよい）
- 通知：
  - 患者のみ、予定時刻に1回プッシュ通知
  - 通知タップで該当の「飲んだ」動線へ
  - 60分超（未服用）時の再通知はMVPではしない
- オフライン：
  - MVPではオフラインキューなし（通信断はエラー表示）
- カレンダー：
  - MVPは「当日（日表示）＋月カレンダーにマーク程度」。週表示や高度な集計はOut of Scope

この spec には以下を必ず含めて：
- 用語定義（TAKEN/MISSED/RESOLVED、予定、履歴、在庫）
- 状態遷移（未服用→解消など）と不変条件（取り消し不可など）
- 認可境界（患者本人/家族代理、連携解除後の扱い）
- エラー形式（安定した error code/message の方針）
- PII とログ方針（マスキング/出力禁止）
- 非機能（入力検証、観測性、性能目標は「featureごとに spec で定義」など最低基準）
- Open Questions があれば [NEEDS CLARIFICATION] に列挙（ただし plan 前に0にする前提）
